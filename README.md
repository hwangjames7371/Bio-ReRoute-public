## 무엇을 주장하나

> **병목은 후보를 만드는 일이 아니라, 그럴듯하지만 틀린 후보를 값싸게 걸러내는 일이다.**

가설(약물 · 질환)을 받아 공개 문헌 · 임상 등록부 · 화학 정보에서 **반증을 먼저 찾고**, 근거가 모자라면 판정하지
않고 **보류**한다. 판정마다 근거 문장 원문 · PMID · 가중치가 남는다. 평가는 «얼마나 잘 찾았나» 가 아니라
**기각이 맞았나 · 맞는 것을 버렸나 · 모르면 모른다고 하나 · 모델 기억이 아닌가** 순서로 본다.

|---|---|---|
| 기각 정밀도 | **94.3%** (99/105) | 96.8% (122/126) |
| 성공한 약을 기각 | **1.6%** (6/387) | 1.0% (4/387) |
| 보류(«모른다») | 61.1% | 57.5% |
| Brier (널 0.250) | 0.219 · Platt 보정 후 0.212(770쌍) | 0.218 — 구별되지 않는다 |

- **전체에서는 모델 기억이 더 잘 거른다 — 우위를 주장하지 않는다.** 파이프라인의 몫은 모델이 «모름» 이라 답한

## 봉인을 직접 확인하는 법

```
py -c "import hashlib;print(hashlib.sha256(open('사전명세_라우터분기.md','rb').read()).hexdigest())"
```

위 값이 `사전명세_라우터분기_봉인.json` 과 `봉인해시_공개등록.txt` 에 적힌 값과 같아야 한다. 등록 파일의 시각은
OpenTimestamps 클라이언트로 확인한다(`pip install opentimestamps-client` → `ots verify 봉인해시_공개등록.txt.ots`).
**제3자 증명이 걸린 것은 등록 파일에 적힌 명세뿐이다** — 나머지 명세는 우리 컴퓨터가 만든 커밋 시각이 증거라
약하다(`커밋기록_요약.txt` · 보고서 §3.4).

해시는 **바이트**를 잰다. 이 저장소는 git 이 줄바꿈을 바꾸지 않게 해 두었다(`.gitattributes` 의 `* -text`) —
`git clone` 이든 ZIP 내려받기든 원본과 같은 바이트가 온다.

홀드아웃 동결도 같은 방법으로 대조한다 — `bench_holdout_freeze.json` 이 원천 풀(`bench_tn_pool_v2.csv`)과
나눈 두 파일(`bench_holdout_dev.csv` · `bench_holdout_sealed.csv`)의 sha256 과 나누는 규칙을 적어 두었다.
이 동결 시각은 우리 컴퓨터가 적은 것이라 제3자 증명보다 약하다.

## 실행

```
py -m pip install -r requirements.txt           # 판정 경로는 API 키가 필요하다 (.env)
py -m bioreroute.netcheck                       # 외부 조회가 살아 있는가 (LLM 0회)
py -m bioreroute.run --pair "metformin / Breast Cancer"
py -m bioreroute.bench.perfcard                 # 보고서 §4.1 성능 표 (LLM 0회 · 결과 파일에서)
py -m bioreroute.bench.calibrate --fit 궤적_0912.json --eval 홀드아웃_본선모델.json --compare-fit bench_results.json
py -m bioreroute.bench.faithful --state 상태_홀드본선_B5.json
py web/server.py                                # 로컬 웹 화면 (라이브 검증 · 병으로 시작)
```

**키** — `.env` 에 `DACON_API_KEY`(또는 `BIOREROUTE_API_KEY` · `OPENAI_API_KEY`) · `BIOREROUTE_API_BASE`(OpenAI 호환 주소)
· `BIOREROUTE_MODEL` · `BIOREROUTE_SEED` 를 둔다. 본선 수치는 `gpt-5.6-terra` · seed 42 · 주최측이 제공한 API 로 냈다.
LLM 0회 명령(perfcard · calibrate · faithful 등)은 키 없이 돈다.

보고서 §9 에 재현 명령 전부가 있다. **유료 데이터와 GPU 는 쓰지 않는다.** 캐시는 넣지 않았다 — 그래서 판정 경로를
다시 돌리면 그사이 바뀐 문헌과 LLM 답 때문에 판정이 달라질 수 있다. 그대로 재현되는 것은 상태 파일에서 수치를 다시 내는
명령까지다.

수치를 내는 명령(perfcard · calibrate · prereg · faithful · fragility · labelaudit)은 이 사본을 새 폴더에 풀어 그대로
돌려 확인했다. 회귀 시험(`py -m bioreroute.tests.test_phase2`)은 작업 저장소를 기준으로 짰다 — 발표 생성기 · 실행
스크립트 · 배포 사본을 보는 항목이 있어 이 사본에서는 그 항목이 실패로 뜬다.

## 개발 이력

- 예선 기획서를 준비하던 7~8월에 프로토타입을 만들었다. 그때 올린 옛 데모는 8월 판에 멈춰 있고 본선 제출물이
  아니다 — 본선 데모는 위 주소 하나다
- 본선 개발 기간(9월 7일~10월 2일)에는 주최측 모델로 옮기고, 봉인 홀드아웃을 그 모델로 다시 쟀고, 전문 읽기를
  새로 만들고, 결함을 고치고 검증했다
- 작업 저장소는 비공개다. 그 커밋 기록 중 명세 · 결과 파일에 관한 것을 `커밋기록_요약.txt` 에 뽑아 두었다
- 개발 중 작업 문서 — AI 작업 규칙(`CLAUDE.md`) · 점검 렌즈 답변 일지(`렌즈답변.md`) · 자체 채점표(`심사기준대조.md`) ·
  요강 확인 메모 — 는 넣지 않았다. 본문 몇 곳이 이 파일들을 인용한다. 인용된 금지 규칙(라벨 파이프라인 재실행 ·
  결과를 보고 고친 뒤 같은 벤치로 다시 재기 · 결과 파일 덮어쓰기)은 `재현절차.md §0` 에 같은 내용이 있다

## AI 사용

- 이 시스템은 판정 경로에서 LLM 을 쓴다 — 후보 · 요약 · 기전 분류 · 근거 등급. 인용은 원문 대조를 통과한 것만
  쓰고, 확률은 규칙 기반 로그오즈 합이다(`투명성_연구윤리.md`)
- 개발에도 AI 코딩 도우미를 썼다. 결함 대장이 그 과정에서 나온 실수(도우미의 실수 포함)를 적는다
